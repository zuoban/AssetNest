## 1. 产品概述

### 1.1 背景与痛点

跨境电商商品素材分散在供应商图片、实拍图、AI 生成图、聊天记录、文件夹和压缩包中。一个商品可能同时用于菲律宾 Shopee、菲律宾 TikTok Shop、泰国 Shopee 等多个市场与店铺，导致：

- 同一张图片被反复复制，难以追溯原始文件和生成版本。
- 不同平台的主图、轮播顺序、详情图、SKU 图及 PDP 文案混在一起。
- 产品母图和最终版本被覆盖，无法快速定位已审核素材。
- 上架前重复整理、命名、排序和打包，容易遗漏规格图或使用错误市场的文案。
- 普通网盘不理解商品和上架关系；通用 DAM 又缺少电商业务工作流。

### 1.2 产品定位

AssetNest 是面向跨境电商卖家的自托管数字资产管理平台（DAM），以商品为业务中心，统一管理图片、视频、文档与商品上架内容。

核心闭环：**创建商品 → 导入素材 → 分类与搜索 → 锁定母图 → 维护 SKU → 按渠道组织上架素材和 PDP → 审核 → 导出上架包 → 保留历史版本。**

### 1.3 产品目标

- 一次建立商品档案，多个店铺和市场复用商品资料及原始素材。
- 在同一界面完成素材浏览、分类、检索、审核和上架包整理。
- 在不重复存储无意义副本的前提下管理多个上架版本。
- 原文件可追溯、不可被日常编辑覆盖，最终上架内容可复现。
- 不依赖云服务才能运行，可自行选择本地、S3 或 WebDAV 存储。
- 部署、备份、恢复与迁移过程简单，降低个人维护负担。

### 1.4 首版非目标

不实现订单、库存同步、财务、采购管理、自动广告投放、平台自动发布、复杂组织权限、实时多人协同编辑、分布式部署或独立微服务。首版不要求 AI 自动生成图片，不要求外部模型 API，也不依赖任何收费服务。价格、成本等字段如有需求先作为可选商品备注，不构成 ERP 功能。

## 2. 用户、场景与核心概念

### 2.1 用户角色

| 角色 | 首版权限 |
|---|---|
| 系统管理员 / 个人卖家 | 完整商品、素材、上架、设置、备份和存储管理权限 |
| 未登录访问者 | 仅可访问登录、首次初始化（受控）及必要的健康检查 |
| 运营、设计、审核等协作角色 | P2，首版不建立复杂 RBAC |

首版只支持一个管理员账户和一个工作空间，不开放匿名注册或公开素材分享。可在局域网或私有 HTTPS 域名使用。

### 2.2 典型使用场景

1. 将供应商原图与实拍图导入某款台灯商品，标记为参考素材。
2. 锁定正确外观母图，记录尺寸、颜色、结构与禁止修改项，管理多轮 AI 出图结果。
3. 在不同店铺使用同一商品，但维护独立轮播图、泰文/英文 PDP 和 SKU 图。
4. 从全部素材中筛选「菲律宾 / TikTok / 餐厅场景 / 最终版」。
5. 完成一套上架内容，检查图像、SKU、标题及描述后导出 ZIP，保留发布快照。
6. 将部分或全部历史素材从本地迁移到 S3，旧商品链接和素材引用不发生变化。

### 2.3 领域术语

| 对象 | 定义与关系 |
|---|---|
| Product / SPU | 一款商品的公共档案，包括名称、规格、参考图、母图 |
| SKU | 商品具体销售规格，例如 Gold / Silver / Black，隶属于 SPU |
| Store | 店铺，包含平台、国家或市场、默认语言 |
| Listing | 计划或实际的商品上架链接；首版属于一个 SPU 和一个 Store，同商品可在同店有多个 Listing |
| File | 不可变的物理文件，记录存储位置、哈希、大小和类型 |
| Asset | 具有业务意义的素材记录，包含名称、分类、标签、关联对象 |
| Asset Version | 某素材的具体文件版本，引用 File，历史版本不可就地替换 |
| Asset Set | Listing 下按用途组织的有序素材集合，如轮播图、详情图、SKU 图 |
| PDP | 商品详情页文本内容，包括标题、描述、卖点、规格与语言 |
| Release | 某次确认上架的不可变内容快照，固定引用素材版本、PDP 版本和导出规则 |
| Export | 根据 Release 生成的上架包及导出任务记录；不代表已成功发布到外部平台 |

物理文件与业务素材必须分离。一个物理文件可被多个素材版本引用，一个素材版本可以被多个 Listing 引用。首版同一个 Listing 对应一个 SPU；合售多个不同 SPU 的复杂链接以后再扩展。如只是同款商品不同款式，可用 SKU 规格维度表达。

### 3.2 UI/UX 要求

- 中文 UI，内容语言独立：PDP 可使用英语、泰语及其他语言；界面国际化为 P1。
- 桌面端优先，浏览器窗口缩放时保持可用；移动端首版支持浏览、检索和查看详情，不要求完整复杂编辑。
- 素材页面采用三栏：左侧分类、中央虚拟化缩略图/列表、右侧属性面板；提供全屏预览。
- 商品页面以封面和名称为主，展示 SKU 数、关联渠道、素材状态；提供网格/列表切换。
- 统一搜索、筛选、批量选择、拖拽导入、轮播拖拽排序、快捷操作。
- 明确区分原图、当前版本、锁定母图、审核状态和已发布快照；不以颜色作为唯一状态标识。
- 上传、迁移、打包等耗时任务应显示进度、可读错误及重试入口，不阻塞正常浏览。
- 支持浅色和深色主题（P1），首版不为了主题引入额外 UI 框架。

## 4. 功能需求（P0）

### FR-01 初始化与工作台

- 首次启动引导创建管理员，初始化 SQLite 和默认本地存储，不要求外部账号。
- 已初始化实例不能通过重新访问初始化入口重置管理员；提供受宿主机控制的管理员恢复机制。
- 工作台展示商品、素材、待审核、上架草稿、最近活动、正在执行及失败任务；统计按真实数据库记录计算。
- 默认首页快速新建商品、导入素材和创建上架链接。

验收：空数据实例可完成初始化并登录；重启后账户、设置和资料仍存在；未登录不能读取业务 API 或素材。

### FR-02 商品与 SKU 管理

- 商品支持创建、编辑、归档、软删除、恢复、搜索；SPU 编号在工作空间内唯一，内部主键独立于显示编号。
- 商品字段：SPU、中文名称、可选英文名称、类别、封面、品牌/型号、供应商名称与链接、备注、业务状态、创建与修改时间。
- 支持按键值维护自定义规格，例如材质、尺寸、容量、色温；允许单位和排序，不按品类硬编码。
- 支持定义规格维度，例如颜色、尺寸、Version；SKU 支持自定义编码、名称、规格组合、专属参数和图片。
- 同一商品下 SKU 规格组合不得重复；SKU 编码全工作空间唯一。允许单规格商品仅建立一个默认 SKU。
- 商品公共规格与 SKU 专属规格分离，生成 PDP 时可人工选择引用；不得自动覆盖已编辑文案。
- 归档商品保留历史 Listing 和 Release；删除有历史引用的商品时提示影响，禁止直接物理清除历史引用对象。

验收：创建一个商品及三个颜色 SKU，修改公共名称不会影响 SKU 标识或历史上架快照；搜索商品编码可进入正确详情。

### FR-03 素材导入与文件管理

- 支持文件选择、拖拽、多文件/目录导入（目录导入受浏览器能力影响，提供批量文件回退）。
- 支持图片（JPEG、PNG、WebP、GIF 等）、视频（MP4、WebM 等）、文档（TXT、MD、PDF）、表格、ZIP 和其他允许的文件类型；不要求所有格式在线预览。
- 可导入到商品、逻辑文件夹或待归类区域；可选择启用的目标存储，未选择则使用默认存储。
- 文件存储前后计算和记录 SHA-256；同存储空间内按哈希去重，允许重复建立业务素材记录，不能误合并标签或用途。
- 记录原始文件名、业务显示名、扩展名、MIME、文件字节数、尺寸（可提取时）、时长（可提取时）、来源、创建时间、存储状态。
- 普通重命名、移动逻辑文件夹、修改标签不改动底层文件，也不改变已冻结版本。
- 批量操作：移动、添加/移除标签、关联商品、审核、下载、软删除；危险操作明确二次确认。
- 可将已有素材关联至多个商品或上架集合，不要求复制实际文件。
- 支持收藏、备注、来源链接和可选 AI 生成提示词文本（仅保存文本，不调用外部 AI）。
- 上传采用流式处理或有界临时文件，设可配置大小、并发和临时磁盘限制；失败须明确显示并允许重试。
- ZIP 首版按普通文件归档与下载，不自动解压不可信压缩包；PSD、RAW 等不可解码格式提供文件图标与下载。

验收：同一张图片重复导入两个商品只写入一份同存储物理文件，两条素材记录可分别编辑；其中一条软删除不影响另一条；不支持预览的文件仍可下载。

### FR-04 预览、标签、分类与搜索

- 图片自动生成本地缩略图，支持原图查看、缩放、前后切换、适屏及 100% 查看；预览不能替代或修改原图。
- 浏览器可解码的视频支持播放与 Range 请求；无法解码时提供下载和状态提示。视频转码及自动封面为 P1，可选 FFmpeg，不作为首版强制依赖。
- 支持文本/Markdown 安全预览，PDF 使用浏览器或下载回退；不得直接执行不可信 HTML、SVG 或脚本。
- 支持多级标签和逻辑文件夹。标签维度包含市场、平台、用途、颜色、场景等，用户可新增和编辑；审核状态为独立字段，不仅是标签。
- 预置用途：供应商原图、实拍、参考图、母图、主图、轮播图、详情图、SKU 图、视频、PDP、广告、竞品、其他。
- 搜索覆盖 SPU、SKU、商品名称、素材名、原文件名、标签、备注、PDP 标题及正文；支持组合筛选商品、店铺、市场、平台、用途、类型、状态、尺寸、日期与存储空间。
- 搜索提供分页或游标，结果支持排序；中文和泰文至少支持准确的字面子串查询，全文索引不能返回结果时有合理回退。暂不要求 AI 语义检索。
- 支持保存常用筛选组合（P1），首版提供固定待归类、收藏、待审核等入口。

验收：组合筛选「商品 A + PH + TikTok + 餐厅 + 已通过」不混入不匹配记录；中文、泰文名称和英文 SKU 的测试查询均能检索；损坏缩略图可重新生成。

### FR-05 母图、版本与审核

- 每个商品允许锁定一个或多个母图版本（例如正面、侧面、佩戴形态）；指定一个默认母图。
- 母图记录锁定的具体 Asset Version，不随素材当前版本变动；解除锁定或替换母图需明确确认并记录时间与备注。
- 商品支持维护外观约束：结构、比例、颜色、尺寸、禁止修改项、参考图与文本说明。
- 素材可追加新版本，保存版本号、文件、修改说明、生成提示词、参考素材链接和时间；旧版本保留，不能被覆盖。
- 支持选择历史版本为当前版本；实际切换只改变当前指针，不删除历史。
- 支持母图与待审核图片并排对比，并显示尺寸、比例和文件信息；不承诺 AI 自动判断外观一致性。
- 审核按素材版本记录：待审核 / 已通过 / 已拒绝。上传新版本默认待审核；可写审核备注。已通过并不代表已上架。
- 草稿或工作集合可调整版本引用；已经创建的 Release 始终引用原具体版本，不随当前指针变化。

验收：锁定 V1 后上传 V2，不改变母图 V1；对 V2 的审核不改变 V1 的状态；已发布快照仍能下载原 V1 文件。

### FR-06 平台、市场、店铺及 Listing 管理

- 平台、市场、语言为可配置字典，预置 Shopee、TikTok Shop、Lazada；PH、TH、MY、VN、SG、ID 等；en、th、zh 等语言代码。
- Store 字段包括名称、平台、市场、默认语言、备注、状态；同平台同国家允许多店。
- Listing 字段：所属商品、店铺、展示名称、语言、外部商品 ID/链接（可空）、状态、备注；同店可存在多个 Listing。
- Listing 绑定参与销售的 SKU 子集、渠道专属 SKU 编码或名称及专属素材；商品 SKU 不必全部参与每个 Listing。
- 支持从已有 Listing 复制为新草稿：复用素材版本引用并独立维护顺序和文案；不能共享可变草稿本身。
- Listing 状态：草稿、已准备、已上架（手动标记）、已归档。导出或生成 Release 不自动标记已上架。
- 外部平台发布状态不自动同步；界面明确为用户维护的数据。

验收：同一 SPU 创建 PH Shopee、PH TikTok、TH Shopee 三个 Listing，修改其中一个店铺首图和文案，不改变其他 Listing。

### FR-07 上架素材集合与可视化排序

- Listing 内独立维护主图/轮播图、详情图、SKU 图和视频集合；按平台模板配置是否启用、数量及要求。
- 轮播集合为有序列表，第一位作为主图；支持拖拽调整、替换、移除、批量添加及恢复排序。
- 详情图支持按序显示和连续预览，兼容 9:16 及其他比例；SKU 图须关联到具体 Listing SKU，不用文件名猜测归属。
- 集合项始终引用具体素材版本，允许用户主动升级至新版本；界面提示存在更新，但不得自动替换。
- 显示素材分辨率、比例、大小、审核状态及重复项提醒。
- 支持从商品公共素材库或其他 Listing 选择已有版本，不重复上传。

验收：对九张轮播图拖拽排序后刷新仍保持顺序；替换一个 SKU 图只更新对应 SKU；历史 Release 中的素材顺序不受影响。

### FR-08 PDP 文案管理

- 每个 Listing 可维护标题、短描述/卖点、完整描述、规格表、包装清单及使用说明；可选 SEO 关键词和备注。
- 可按 Listing 语言创建文案版本，支持 UTF-8 文本、Markdown 或结构化字段；首版不要求富文本编辑器。
- 支持保存草稿、生成不可变版本、复制到其他 Listing、恢复历史版本为新草稿、复制单字段与全文。
- 显示标题字符数和模板规则提示。可配置计数方式；默认按 Unicode 码点计数，不声称等同所有平台的实际计数规则。
- 商品公共规格可导入编辑器供人工修改；更新商品档案时只提示差异，不自动重写历史文案。
- 支持英文、泰文和中文混合输入，预览与导出保持编码一致。

验收：创建 EN、TH 文案；复制历史版本为新草稿后修改泰文标题，原历史文案与其他 Listing 不变；导出的 UTF-8 文本不乱码。

### FR-09 上架检查、Release 与 ZIP 导出

- 每个市场/平台可配置导出模板：文件夹名称、命名规则、主图与轮播数量、比例容差、最小分辨率、文件大小、允许格式、标题限制、必填 PDP 字段、SKU 图是否必需。
- 模板提供可修改的示例配置，例如轮播目标 9 张、比例 1:1、详情 9:16、标题最多 100 字符。这些是业务示例，不是已核实的现行平台规则，使用者可按后台要求调整。
- 检查结果区分阻断错误和提示；缺失文件、存储读取失败、未审核或被拒绝素材等按配置阻断正式 Release。用户可以导出明确标记的草稿包，但不得伪装成已审核正式包。
- 检查应验证实际引用的具体版本。创建 Release 时保存完整快照：Listing 字段、SKU 映射、素材版本及顺序、PDP 版本、模板版本和检查结果。
- Release 创建后不可编辑；变更内容时新建 Release。可以从旧 Release 恢复为新草稿，但不覆盖现有历史。
- ZIP 由任务系统生成，提供进度、失败原因、重试、下载与过期提示。流式读取远程原文件，不将全部大文件放入内存。
- ZIP 包含按用途排序的图片、视频、SKU 图、PDP 文本/JSON 和 manifest；文件名安全化，解决重复命名并禁止路径穿越。
- 首版默认导出原文件，不静默转码、缩放、增加水印或改写内容。批量转格式和自动压缩为 P1；规则不满足时提示用户调整。
- 导出文件本身可过期清理，只要 Release 所引用的文件与规则仍在，就能重新生成内容一致的 ZIP；不要求压缩包二进制哈希一致。

示例：

```text
UFO-001_PH_Shopee_StoreA_R003.zip
├── 01_Carousel/
│   ├── 01_Main.jpg
│   └── 02_Lifestyle.jpg
├── 02_SKU/
│   ├── UFO-001-GD.jpg
│   └── UFO-001-BK.jpg
├── 03_Detail/
│   └── Detail_01.jpg
├── 04_Video/
├── 05_PDP/
│   ├── Title.txt
│   ├── Description.txt
│   └── Specifications.json
└── manifest.json
```

manifest 至少包含 schemaVersion、releaseId、商品/店铺/市场/平台标识、语言、生成时刻、模板标识以及每个导出文件的相对路径、来源版本 ID、SHA-256、大小和顺序；不包含存储密码、签名 URL 或服务器绝对路径。

验收：构建一套 9 图、3 SKU、详情图和英文 PDP 后导出，文件顺序、扩展名、内容与 manifest 一致；修改当前草稿后，旧 Release 重导出的素材哈希和文案内容仍一致；缺图/未审核时给出准确提示。

### FR-10 回收站与删除保护

- 商品、Listing、素材执行软删除；回收站支持恢复，默认保留期建议 30 天，可配置。
- 锁定母图、当前集合、Release、正在执行的任务及可恢复版本引用的文件禁止物理删除。
- 只在没有任何有效引用且超过安全保留期后，允许通过垃圾回收任务清理物理文件；重复执行安全。
- 远程删除失败进入待重试状态，不得先删除数据库记录造成失联；用户可看到清理错误。
- 清理缓存不删除原文件、SQLite 或发布快照；清理导出包不删除 Release。

验收：一个文件被两家店引用，删除第一家草稿不影响第二家；删除有 Release 引用的素材时历史包仍可下载或重建；解除软删除可恢复原关系。

## 5. 可插拔存储系统（P0，架构硬约束）

### 5.1 存储支持与边界

| 类型 | 配置参数 | 说明 |
|---|---|---|
| Local | 名称、根目录 | 默认；本地硬盘或宿主机挂载目录 |
| S3 Compatible | endpoint、region、bucket、prefix、access key、secret key、path style、可选 session token | AWS S3、R2、MinIO 等兼容服务；实际兼容性需测试 |
| WebDAV | base URL、root path、用户名、密码/令牌 | Nextcloud、NAS 等 WebDAV 服务；能力取决于服务端实现 |

系统始终使用本地持久化 SQLite。数据库与 WAL/SHM 文件不得放到 S3、WebDAV 或不满足 SQLite WAL 锁语义的网络文件系统。图片、视频、文档可远程存放，缓存仍在本地。应用不要求安装 MinIO 服务。

### 5.2 存储配置与管理

- 支持多个已配置 Provider 共存，具有稳定 ID、名称、协议、配置引用、启用状态和默认标志；恰好一个可写默认存储。
- 首版提供配置文件及环境变量配置；Web 界面展示存储列表、状态、连接测试、默认存储切换及迁移入口。UI 修改连接参数和密钥为 P1，避免首版密钥管理过度复杂。
- 配置文件是 endpoint、根目录等连接参数的唯一来源；SQLite 记录稳定 ID、默认 Provider ID、可用状态和业务关联，不能出现两个相互冲突的默认配置。首次初始化读取配置默认值，之后以数据库默认设置为准。
- 敏感凭证使用环境变量或宿主机 secret 文件引用；不写入数据库明文、前端响应、任务日志和导出包。
- 连接测试使用随机临时对象，验证写入、读取、完整性、删除；区分认证失败、超时、权限不足等，不触碰已有业务文件。失败清理留下的临时对象。
- 切换默认存储只影响之后导入的文件，不迁移历史文件；重命名 Provider 不改变其 ID。
- 禁用有引用的存储时允许暂时离线但显示不可访问；禁止删除仍有文件引用的 Provider 配置。不能通过原地修改 bucket 或根目录来伪装迁移。
- 配置缺失、断网或服务不可用时仍能查看本地业务元数据，受影响文件显示离线状态，禁止静默丢失或自动写入其他 Provider。

### 5.3 适配器能力

所有业务模块只使用统一 StorageProvider 接口，禁止直接调用特定厂商 SDK。

```ts
interface StorageProvider {
  put(key: string, body: ReadableStream<Uint8Array>, options?: PutOptions): Promise<void>;
  get(key: string, options?: GetOptions): Promise<ReadableStream<Uint8Array>>;
  stat(key: string): Promise<FileStat>;
  exists(key: string): Promise<boolean>;
  delete(key: string): Promise<void>;
  testConnection(): Promise<ConnectionResult>;
}
```

以上是接口契约示意，PutOptions 等类型和 Node/Web Stream 边界由技术设计明确。可选能力（Range、签名 URL、分片上传、服务端复制等）通过 capability flags 表达；不要求 WebDAV 与 S3 完全等价。WebDAV 不支持 Range 时降级为完整流式读取或下载，不承诺流畅拖动进度条。

Local 防止路径穿越、符号链接逃逸及写入根目录以外；S3 兼容自定义 endpoint、path-style 和 prefix；WebDAV 正确处理 URL 编码、父目录创建及方法错误。默认所有访问走应用鉴权代理，可选 S3 短时签名 URL，但不能使 bucket 公开。

### 5.4 文件存储、去重与一致性

- 原文件不可变，推荐对象路径 `originals/<sha256前两位>/<sha256>`；扩展名与 MIME 保存在元数据，不依赖对象路径。
- 对同一 Provider 内相同字节内容去重，数据库约束 `(storage_id, sha256)` 唯一。不同 Provider 可保留独立物理副本，不为跨 Provider 全局去重引入复杂副本模型。
- 原始文件名、逻辑目录和业务名称保存在数据库；直接浏览存储桶不会显示商品逻辑结构，须提供开放格式导出和清单以保证可迁移性。
- 文件导入顺序：暂存并流式计算哈希 → 检查目标存储去重 → 写入/验证 → 提交 SQLite 引用和素材版本 → 生成缓存。竞争条件由唯一约束和幂等任务处理。
- 远程存储与 SQLite 之间没有分布式事务，必须以任务状态、临时对象和定期核对处理崩溃产生的孤儿文件；不能先将未写成功的对象标记为 ready。
- 仅可在受控临时目录或命名空间清理经确认未引用且超出保留期的对象；不对用户整个 bucket/WebDAV 根路径进行不加区分的删除。
- 缩略图、预览、临时文件与 ZIP 默认存本地缓存或导出目录；缓存容量及回收策略可配置，原图不受缓存淘汰影响。

### 5.5 存储迁移

1. 用户选择来源、目标及文件范围，展示预计文件数量和字节数；列出因共享引用也会受影响的文件。
2. 确认目标可写，建立持久化迁移任务。以物理文件为单位迁移，不按商品复制所有重复引用。
3. 流式复制，验证字节数及 SHA-256；目标已有相同哈希时先校验再复用。
4. 在 SQLite 短事务内更新该文件的存储位置；若目标已存在相同物理记录，安全合并引用，保持 Asset Version 与 Release ID 不变。每个文件的切换可幂等重试。
5. 核对全部目标文件，确认访问正常。默认保留来源对象供回退/人工核对，用户另行确认后清理；中断的迁移可从已完成文件继续。
6. 迁移过程中，未切换文件从来源读取，已切换文件从目标读取；应协调并发清理任务，不清理正在迁移的对象。

验收：Local→S3、S3→WebDAV、WebDAV→Local 各完成代表性图片/视频迁移；模拟远程错误和应用重启，任务可恢复或安全重试，文件内容、引用、上架历史保持一致。未经验证的目标文件不得替换源文件关联。

以下为概念级 Schema，不要求为每个概念盲目拆表；实施时补充字段类型、外键、索引、迁移和测试。主键建议稳定 UUID，所有时间统一 UTC 存储，界面按配置时区显示。

PDP 冻结版本可在 Release 快照中保存内容并记录来源版本；素材版本引用必须具备可查询关系，不能只在 JSON 内保存路径，避免误清理。

关键不变量：

- 所有已提交的素材版本指向 ready 文件记录；一个文件可以被多个版本引用。
- `SPU`、`SKU code` 全工作空间唯一；同商品下规格组合唯一；同一素材下版本号唯一；同 Listing 下 Release 编号唯一。
- 集合的排序位置、SKU 与 Listing 归属必须校验；SKU 图不得关联其他 Listing 的 SKU。
- 当前版本必须属于对应 Asset；母图锁定的是具体版本；已冻结 Release 的内容不可更新。
- 外键、唯一约束、事务、软删除规则和迁移脚本必须通过测试。跨表业务规则在事务内校验；避免长时间持有 SQLite 写事务。
- 标签、文件夹、市场与店铺等业务关系不依赖物理文件名或固定目录。

## 7. 技术架构与低依赖约束

### 7.1 架构

```text
Browser (Web UI)
       │ HTTPS / 本地 HTTP
       ▼
AssetNest 单体应用（Node.js runtime）
├── Web UI / API / Session Auth
├── Product / Asset / Listing / PDP / Release 模块
├── SQLite Repository + 搜索索引 + 持久化任务队列
├── 内置 Worker（受限并发）
├── 本地缓存与媒体处理
└── Storage Adapter
    ├── Local
    ├── S3 Compatible
    └── WebDAV
```

### 7.2 建议技术栈（非用户硬性要求）

| 层 | 建议 | 约束 |
|---|---|---|
| 应用 | TypeScript + Next.js / React | 使用常驻 Node.js runtime；非 Serverless 或 Edge 部署 |
| UI | Tailwind CSS、必要的 shadcn/ui 组件、Lucide | 不引入多个功能重复的 UI 框架 |
| SQLite | 一个受支持的 SQLite 驱动；优先评估运行时内置能力 | 仅在确有收益时使用 Drizzle，不强制 ORM |
| 搜索 | SQL 索引、FTS5（环境支持时）与字面匹配 | 中文/泰文专项测试；不依赖外部搜索服务 |
| 文件处理 | Node.js fs/stream、crypto、必要的 ZIP 库 | 流式读写，避免全文件驻留内存 |
| 远程存储 | 适量 S3 SDK 与 WebDAV 客户端 | 适配器隔离，按配置启用 |
| 图片 | 一个可靠图片处理库（建议 Sharp） | 缩略图生成限制尺寸、像素与资源消耗 |
| 视频 | 浏览器播放优先 | FFmpeg 可选增强，不为首版强制安装 |
| 队列 | SQLite jobs + 应用内 Worker | 不使用 Redis、RabbitMQ 或独立队列服务 |
| 部署 | Docker 单容器，持久化卷 | 不要求 PostgreSQL、MySQL、Redis、MinIO、Elasticsearch |
| 测试 | 单元、集成与浏览器 E2E | 测试工具属于开发依赖，不额外部署运行服务 |

SQLite 每个连接启用 `foreign_keys` 和合理的 `busy_timeout`，本地数据库采用 WAL。数据库迁移版本化，启动时执行兼容性检查；可靠性优先，事务持久化设置由技术设计评估。应用首版仅支持单实例，不得多个容器共享同一个 SQLite 写入卷。

### 7.3 持久化任务

用于上传后处理、缩略图、ZIP、迁移、备份及清理。任务状态：queued、running、succeeded、failed、cancelled；运行中具有租约和心跳，重启后可以回收过期租约并安全重试。任务记录可查询，进度不是必然百分比，未知长度任务显示阶段与已处理数量。取消为协作式安全取消，不保证任意远程 IO 立即终止。

默认并发建议 2，可配置；同一文件的迁移和清理互斥。长耗时操作在短数据库事务之外执行，任务步骤具有幂等性。业务失败与暂时网络错误分别处理，重试次数及退避时间可配置。

### 7.4 配置与部署示例

```yaml
# /config/config.yaml（建议契约，尚非实际运行配置）
app:
  name: AssetNest
  port: 3000
  locale: zh-CN
  timezone: Asia/Shanghai
  dataDir: /data

database:
  path: /data/db/assetnest.db
  wal: true

storage:
  # 仅首次初始化时使用，之后默认项由数据库设置管理
  default: local
  providers:
    local:
      type: local
      root: /data/assets
    r2:

      accessKeyId: ${S3_ACCESS_KEY}
      secretAccessKey: ${S3_SECRET_KEY}
      forcePathStyle: false
    nas:
      type: webdav
      endpoint: ${WEBDAV_URL}
      root: /assetnest

      password: ${WEBDAV_PASSWORD}

  path: /data/cache

```

未使用的远程 Provider 应从配置删除或显式禁用，不应要求用户提供其环境变量才能使用 Local。配置加载时校验协议、路径、重复 ID、必要字段和变量；密钥变量不能回显。

```yaml
# compose.yaml（目标部署示例；镜像名称尚未发布）
services:
  assetnest:
    image: assetnest:1.0.0
    restart: unless-stopped
    ports:
      - "127.0.0.1:3000:3000"

      - .env
```

默认绑定本机用于私有访问；局域网或反向代理部署时按网络结构调整绑定地址，远程访问使用 HTTPS 和身份验证。容器内部应用监听可达接口，运行时尽量使用非 root 用户。升级前创建一致性备份并固定镜像版本，不使用不可控的自动 latest 更新。

持久化目录：`/data/db`（数据库）、`/data/assets`（Local 原文件）、`/data/cache`（可重建）、`/data/imports`（临时导入）、`/data/exports`（临时包）、`/data/backups`（备份）；`/config` 管理非敏感配置及环境变量引用。

## 8. 备份、恢复和数据可移植性（P0）

- 区分「元数据备份」与「完整备份」：前者保存一致性 SQLite 快照、配置引用、对象清单；后者额外保存所有被引用的原始文件，可在另一存储恢复。界面明确元数据备份不能单独恢复丢失的远程原文件。
- 使用 SQLite 一致性备份机制，不能简单复制正在写入的 DB 文件而忽略 WAL。备份清单来自同一快照，备份执行期间保护快照引用对象免被物理清理。
- 完整备份包含版本号、对象 SHA-256、大小、相对路径及业务数据；不要求包含可重建缓存和临时导出包。远程文件通过适配器流式读取。
- 本地/远程备份位置可配置；首版至少提供下载完整备份与宿主机路径保存。周期性备份与远程增量备份为 P1。
- 默认备份不包含明文存储凭证，恢复时需要用户重新提供连接配置；明确提示独立保存必要的环境变量/密钥，并定期复制备份到独立设备。
- 恢复需进入维护模式：验证格式、Schema 兼容性、哈希、文件存在性和目标存储权限，先恢复到临时目录/对象命名空间，全部验证后切换；失败不破坏当前数据。
- 恢复支持重建缩略图与搜索索引；迁移或重新部署后重新关联存储 Provider，不依赖固定域名和绝对文件路径。
- 提供标准目录结构的批量素材导出和 JSON manifest，避免用户只能通过应用读自己的原始数据。

验收：从另一台干净实例恢复含商品、SKU、多版本、Release、Local 与远程原文件的完整备份；校验记录数、文件哈希与历史包内容；模拟损坏备份时保留旧实例数据。

## 9. 安全、可靠性和性能需求

### 9.1 安全

- 密码使用成熟的带盐密码哈希实现；会话采用 HttpOnly Cookie、合理的 SameSite/Secure 策略和过期机制。修改状态的请求防 CSRF；登录限速。
- 所有素材、下载、导出、设置和 API 请求都执行服务端授权，不依靠前端隐藏按钮。默认对象存储私有。
- 文件名和对象 key 规范化，防目录穿越、任意文件读取、ZIP 路径穿越与恶意符号链接；不执行上传内容，不在应用同源直接运行不可信 HTML/SVG/脚本。
- 限制上传尺寸、并发、媒体解码像素数、内存与临时磁盘，验证文件类型；对超限或损坏媒体给出可读错误。
- 远程 Provider 仅管理员配置，允许明确配置私有 NAS，但限制协议和重定向，避免任意 URL 读取；敏感凭证不进入日志或浏览器。
- 记录重要行为：登录失败、删除/恢复、母图替换、版本创建、Release、存储修改、迁移、备份与恢复。不记录密码或签名 URL。
- 不默认上传图片、PDP 或遥测到外部服务；AI、外部同步如后续加入应明确用户授权并可关闭。

### 9.2 可靠性与兼容性

- 服务异常重启后，已确认事务、素材引用、任务记录和已创建 Release 保持一致。
- 远程存储离线不能导致整个商品中心崩溃；本地元数据仍可查看，失败对象和任务可重试。
- 缩略图和搜索索引可重建；原图不可静默替换或降质。所有读取失败都有状态提示。
- 支持当前主流 macOS Chrome/Safari 与 Windows Chrome/Edge 的桌面浏览；具体最低版本在开发阶段确定。
- Docker 构建应考虑 linux/amd64 和 linux/arm64；支持能力以 CI 构建与实际测试结果为准。

### 9.3 建议性能与容量验收目标

以下是设计目标，不是已实测结果；基准环境建议 4 vCPU、8 GB RAM、本地 SSD、单实例、1 个活跃管理员，远程存储网络耗时单独记录。可按实际机器调整。

| 指标 | 首版目标 |
|---|---|
| 测试数据规模 | 1,000 商品、5,000 SKU、50,000 素材记录 |
| 常规元数据搜索 | 温缓存、典型条件 P95 ≤ 500 ms（服务端） |
| 资源列表首屏 | 缩略图已生成、本地局域网条件下 ≤ 2 秒 |
| 大文件上传 | 流式或有界暂存；默认单文件 1 GiB 上限，可配置 |
| 批量导入 | 100 个普通商品图片可排队，页面可继续浏览；失败文件独立报告 |
| 导出与迁移 | 可见进度、可安全重试、受限并发，内存不随总素材体积线性增长 |
| 重启恢复 | 正常完成的写入不丢失；中断任务可恢复或重试 |

SQLite 不要求无限横向扩展，也不预设一定能满足任何给定规模；如实际性能不达标先优化索引、分页、缓存和查询，再考虑架构变化。

## 11. 迭代路线与开发顺序

| 阶段 | 交付范围 | 阶段验收 |
|---|---|---|
| M0 技术基础 | 项目骨架、配置、SQLite 迁移、认证、Docker、测试框架 | 单容器、本地持久化、登录与健康检查 |
| M1 素材核心 | 商品/SKU、Local 适配器、导入、去重、标签、预览、搜索、回收站基础 | 可独立使用的商品素材管理器 |
| M2 存储完整性 | S3、WebDAV、配置管理、默认切换、任务队列、迁移、备份 | 三种存储及故障恢复验证通过 |
| M3 电商工作流 | 店铺、Listing、母图与版本、审核、轮播、SKU 图、PDP | 可维护三个渠道且互不影响 |
| M4 交付与加固 | 模板、Release、ZIP、历史导出、完整恢复、安全和性能测试 | AC-01 至 AC-15 通过或记录明确待解决阻断项 |

实施顺序不代表承诺工期；M0–M4 全部完成才称为 v1.0。允许每个阶段独立运行、演示和提交，减少返工。

### P1：体验与效率增强

- 批量裁剪、压缩、格式转换、尺寸检查、图片对比增强；可选 FFmpeg 视频封面与转码。
- 保存智能筛选、浏览器素材采集、目录监控、ZIP 安全导入、重复/相似图查找、批量编辑元数据。
- Web 端安全配置远程连接、计划备份、增量备份、主题、UI 多语言、PWA 安装体验。
- 可选 OCR、AI 自动标签、语义搜索、文案生成；使用单独的 AI Provider 接口，默认关闭，不阻塞无 AI 的正常流程。

### P2：业务扩展

- 团队账户与角色、审批流、共享链接和协作；多 SPU 合售映射。
- Shopee/TikTok 等平台 API、ERP 对接、自动发布、数据同步、浏览器扩展深度集成。
- 将素材版本关联 CTR、CVR 等实际运营效果，支持 A/B 测试数据管理；必须来自可验证的真实数据。

## 12. 风险、取舍与待确认事项

| 风险或取舍 | 处理原则 |
|---|---|
| SQLite 单写入者与单实例限制 | 短事务、有限 Worker 并发、索引和压力测试；暂不扩展集群 |
| WebDAV/S3 实现差异 | 最小通用能力 + 可选能力检测；真实服务集成测试 |
| 远程流量与延迟 | 本地缩略图缓存、流式读取、明确下载/迁移进度 |
| 文件与数据库跨系统一致性 | 暂存、校验、幂等任务、延迟清理和恢复测试 |
| 内容寻址使物理目录不直观 | 提供逻辑目录、开放文件清单和标准目录导出 |
| 不同平台规则频繁变化 | 可配置版本化规则模板；不把示例当官方硬限制 |
| 备份很大、缓存占盘 | 区分元数据和完整备份，设置容量预算与保留策略 |
| AI 出图变形或误审核 | 母图锁定、人工审核、版本追踪；首版不承诺自动质量判断 |

待确认项（不阻塞按本文建议默认启动开发）：产品正式名称与许可证；是否需要首版支持直接索引已有目录而不导入；远程存储具体服务及对象体量；是否必须首版 Web UI 修改存储密钥；是否需要同一 Listing 合售多个独立 SPU；是否需要团队账号。若这些约束改变，应更新 PRD 版本，而不是在实现中默默增加复杂性。

## 13. 开发交付要求（供 Codex 执行）

1. 开始编码前，把本文作为需求基线，输出简短技术设计、数据库 Schema/迁移计划及按 M0–M4 拆分的可验收任务。
2. 优先实现最小垂直闭环：商品 → 上传原图 → 浏览/搜索 → 创建 Listing → 选择版本 → 导出包。随后补齐所有 P0 可靠性能力。

4. 存储访问只能通过统一适配器，禁止将远程凭证、签名 URL 或二进制原图写入 SQLite。禁止破坏历史版本或已创建 Release 的不可变性。
5. 每次变更包含必要数据库迁移、测试和文档更新；不以 Mock 页面、假数据、未接线按钮或未实现的 API 宣称功能完成。
6. 交付至少包括源码、Dockerfile、compose.yaml、.env.example、配置示例、README、升级/备份/恢复说明、测试及验收报告；将关键约束写入 AGENTS.md。
